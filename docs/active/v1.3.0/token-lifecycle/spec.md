# Token 生命周期管理

## Overview

平台用户通过账号密码登录获取访问凭证，凭证支持自动刷新、主动吊销和多设备会话管理。

## Behavior: 登录获取凭证

### Scenario: 正常登录

Given 用户有一个已启用的账号，用户名为 "admin"，密码为 "correct123"
When 用户使用用户名 "admin" 和密码 "correct123" 登录
Then 返回包含令牌信息和用户认证信息的登录结果
And 令牌信息中包含访问令牌、刷新令牌，访问令牌有效期为 900 秒
And 刷新令牌有效期为 7 天

### Scenario: 密码错误

Given 用户有一个已启用的账号，用户名为 "admin"
When 用户使用用户名 "admin" 和错误密码 "wrong" 登录
Then 返回错误"用户名或密码错误"
And 该账号的登录失败次数递增 1

### Scenario: 账号不存在

Given 系统中不存在用户名为 "ghost" 的账号
When 用户使用用户名 "ghost" 登录
Then 返回错误"用户名或密码错误"

### Scenario: 连续失败触发锁定

Given 用户账号已连续登录失败 4 次，锁定阈值为 5 次
When 用户第 5 次使用错误密码登录
Then 返回错误"账号已锁定，请 30 分钟后再试"
And 该账号被锁定 30 分钟

### Scenario: 账号已锁定

Given 用户账号处于锁定状态，剩余锁定时间 20 分钟
When 用户使用正确密码登录
Then 返回错误"账号已锁定，请 20 分钟后再试"

### Scenario: 账号已禁用

Given 管理员已禁用用户账号
When 该用户使用正确密码登录
Then 返回错误"账号已被禁用，请联系管理员"

### Scenario: 超过最大会话数

Given 用户当前已有 5 个活跃会话（最大会话数为 5）
When 用户从新设备登录成功
Then 返回新的访问令牌和刷新令牌
And 最早的会话被自动踢出（其令牌失效）

## Behavior: 验证访问令牌

### Scenario: 有效令牌

Given 用户持有一个未过期、未吊销的访问令牌
When 系统验证该令牌
Then 返回验证通过，附带用户 ID 和过期时间

### Scenario: 令牌已过期

Given 用户持有一个已过期的访问令牌
When 系统验证该令牌
Then 返回错误"令牌已过期"

### Scenario: 令牌签名无效

Given 用户持有一个签名被篡改的访问令牌
When 系统验证该令牌
Then 返回错误"令牌无效"

### Scenario: 令牌已被吊销

Given 用户持有一个已被主动吊销的访问令牌（未过期）
When 系统验证该令牌
Then 返回错误"令牌已吊销"

### Scenario: 缓存服务不可用时验证

Given 缓存服务不可用，用户持有一个未过期且签名有效的访问令牌
When 系统验证该令牌
Then 返回验证通过（跳过吊销检查）

## Behavior: 刷新访问令牌

### Scenario: 正常刷新

Given 用户持有一个未过期、未吊销的刷新令牌
When 用户使用该刷新令牌请求刷新
Then 返回新的访问令牌和新的刷新令牌，访问令牌有效期为 900 秒
And 原刷新令牌立即失效

### Scenario: 刷新令牌被重放

Given 用户的刷新令牌已成功用于刷新一次
When 任意客户端再次使用该刷新令牌请求刷新
Then 返回错误"刷新令牌已失效"
And 该会话的访问令牌和新的刷新令牌均失效

### Scenario: 刷新令牌已过期

Given 用户持有一个已过期的刷新令牌（超过 7 天）
When 用户使用该刷新令牌请求刷新
Then 返回错误"刷新令牌已过期，请重新登录"

### Scenario: 刷新令牌已被吊销

Given 用户的刷新令牌已被吊销（用户已登出）
When 用户使用该刷新令牌请求刷新
Then 返回错误"刷新令牌已失效"

### Scenario: 缓存服务不可用时刷新

Given 缓存服务不可用
When 用户使用有效的刷新令牌请求刷新
Then 返回错误"服务暂时不可用，请稍后重试"

### Scenario: 同一刷新令牌并发刷新

Given 用户持有一个未过期、未吊销的刷新令牌
When 两个请求同时使用该刷新令牌请求刷新
Then 恰有一个请求返回新的令牌对
And 另一个请求返回错误"刷新令牌已失效"

## Behavior: 登出（吊销当前会话）

### Scenario: 正常登出

Given 用户已登录，持有有效的访问令牌
When 用户发起登出请求
Then 该访问令牌和关联的刷新令牌均失效
And 后续使用该访问令牌验证返回"令牌已吊销"

### Scenario: 使用已过期的访问令牌登出

Given 用户的访问令牌已过期，但刷新令牌仍有效
When 用户使用已过期的访问令牌发起登出
Then 关联的刷新令牌被吊销
And 后续使用该刷新令牌刷新返回"刷新令牌已失效"

### Scenario: 缓存服务不可用时登出

Given 缓存服务不可用
When 用户发起登出请求
Then 返回错误"服务暂时不可用，请稍后重试"

## Behavior: 强制登出所有设备

### Scenario: 正常强制登出

Given 用户在 3 个设备上有活跃会话
When 已获用户管理服务授权的管理员对该用户执行强制全部登出
Then 该用户所有设备的访问令牌和刷新令牌均失效
And 后续使用任一令牌均返回错误

### Scenario: 用户无活跃会话

Given 用户当前无任何活跃会话
When 管理员对该用户执行强制全部登出
Then 操作成功（幂等），无副作用

### Scenario: 缓存服务不可用时强制登出

Given 缓存服务不可用
When 管理员执行强制全部登出
Then 返回错误"服务暂时不可用，请稍后重试"

## Constraints

- 令牌验证 P99 延迟 ≤ 50ms（本地校验 + 缓存查询）
- 签名密钥长度 ≥ 256 位
- 单用户最大并发会话数可配置，默认 5
- 访问令牌有效期可配置，默认 15 分钟
- 刷新令牌有效期可配置，默认 7 天
- 刷新令牌每次使用后必须轮换；旧刷新令牌的重放必须吊销整个会话
- 每个会话必须绑定客户端提供的 deviceId；deviceId 缺失时拒绝登录和刷新
- 账号锁定阈值可配置，默认连续失败 5 次锁定 30 分钟
- 用户被禁用后，既有访问令牌最多可继续使用 60 秒；之后该用户全部会话必须失效
- 缓存服务不可用时，验证操作降级放行，写操作（登录/刷新/登出）返回错误
- 强制全部登出不提供公开 REST API，只允许已认证的用户管理服务经内部 RPC 调用
